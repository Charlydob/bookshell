# MCP 2.3 — continuación de PR #586

Compatible con el commit desplegado cce5e1d; sin migración de datos.

- `get_reminder_overview({view: pending|history|all, timezone})`: vista de proyectos y recordatorios heredados con `attention`, contadores y detección de enlaces tarea-aviso existentes. Lectura pura: no cambia estados, no materializa avisos. Consultar `needsReview`; una antigüedad o un título ambiguo no completan una tarea. Un evento pasado solo se excluye con tipo explícito o evidencia estructurada. `source_metadata.obligationKind` permite revertir la inferencia; no se escribe automáticamente. `get_agenda` admite las mismas vistas para las entradas del proyecto y conserva su respuesta en array.
- La lista nativa con status pending y el resumen diario reutilizan la política. Historial/export y búsquedas antiguas conservan su acceso a estados crudos para compatibilidad. Los campos `attention` distinguen estado persistido y clasificación temporal. Los consumidores de búsquedas antiguas deben usar la vista semántica para contar obligaciones, no contar el status crudo.
- Recurrencias: una sola próxima fecha relevante calculada por el mismo servicio extraído del backend existente, sin adelantar fechas guardadas ni crear notificaciones históricas. Las reglas desconocidas se señalan para revisión. No se modifica el CRUD de recurrencias.
- Todas las escrituras de las 23 herramientas heredadas admiten `idempotencyKey` opcional. Enviar una clave por intención y conservarla al reintentar. Se guarda el resultado en el ledger existente, **en la misma transacción/conexión que la escritura y sus avisos/historial**, mediante contexto asíncrono. Payload diferente con misma clave: 409. Omisión conserva clientes anteriores; sin clave no hay garantía de replay. Las lecturas no necesitan clave.
- `reschedule_dependencies` admite `expectedRevision` numérico (el `version` leído de la tarea), `dayMode: elapsed|civil` y `timezone`. El valor por defecto sigue siendo elapsed=24h. Civil requiere IANA y conserva hora local, segundos y milisegundos; en un hueco DST usa el primer minuto válido posterior y en un pliegue usa la selección determinista del servicio existente. Conservar clave y versión al reintentar: el replay sucede antes de comparar la versión. Versiones ajenas/obsoletas no pueden modificar datos.
